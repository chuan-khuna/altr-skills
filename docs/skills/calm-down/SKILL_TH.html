calm-down — หยุด · คิด · ลงมือ

สกิลจัดโครงสร้างงานแบบสองโหมด มันจะสัมภาษณ์คุณ แล้วเขียนเอกสารที่มีโครงสร้างชัดเจน เปลี่ยนไอเดียดิบ ๆ — หรือความตื่นตระหนกตอนงานท่วม — ให้กลายเป็นงานที่ลงมือทำได้จริง

2026-06-13

สกิลนี้ทำอะไร

calm-down ยืนอยู่ตรงกลางระหว่าง “ฉันมีกองงานที่ยังคลุมเครือ” กับ “งานกำลังถูกทำอย่างดี” แทนที่จะปล่อยให้คุณ (หรือเพื่อนร่วมทีม) กระโดดลงไปทำทั้งที่ยังมองไม่ชัด มันจะสัมภาษณ์สั้น ๆ แล้วสร้างเอกสารที่มีโครงสร้างออกมาหนึ่งฉบับ

มันมีสองโหมดสำหรับสองสถานการณ์ที่ช่องว่างนี้มักโผล่ขึ้นมา: การ ส่งต่อ งานให้คนอื่น และการ นำทางตัวเอง ผ่านงานที่ไฟลนก้นอยู่แล้ว

หลักการเบื้องหลัง

ทั้งการส่งต่องานแบบเย็นชาและการรีบทำงานด้วยความตื่นตระหนก ล้มเหลวด้วยเหตุผลเดียวกัน นั่นคือ ลงมือทำก่อนที่จะเข้าใจงาน เพื่อนร่วมทีมได้ตั๋วงานบรรทัดเดียวแล้วเดาเอา ส่วนคนที่ใกล้เดดไลน์ก็เปิดสิบห้าแท็บแล้วทำงานที่เสียงดังที่สุดก่อน calm-down แทรกการหยุดพักอย่างตั้งใจหนึ่งครั้ง แล้วพาเดินผ่านสามจังหวะ

01 หยุด (Stop)

ตัดวงจรสัญชาตญาณที่จะรีบลงมือ ระบุงานและเวลาที่คุณมีจริง ๆ การหยุดนี้ถูกตีกรอบใหม่ว่าเป็นการ “เร่งให้เร็วขึ้น” ไม่ใช่การถ่วงเวลา

02 คิด (Think)

ถูกซักทีละคำถาม แต่ละคำถามมาพร้อมคำตอบที่แนะนำไว้ ซักจนกว่างานจะถูกแตกย่อยและเข้าใจชัด คำตอบที่คลุมเครือจะถูกซักต่อ ไม่ใช่รับไว้เฉย ๆ

03 ลงมือ (Act)

สร้างเอกสารออกมาแล้วลงมือทำจากความชัดเจน ความคิดอยู่บนกระดาษแล้ว ไม่ใช่วนเวียนอยู่ในหัวอีกต่อไป

สองโหมด

หลักการเดียว สองสถานการณ์ คุณเลือกโหมดจากสิ่งที่คุณกำลังพยายามจะทำ

calm-down assign

ส่งต่องาน

สร้างเอกสารส่งต่อที่เพื่อนร่วมทีม — หรือ AI agent — หยิบไปทำได้ทันทีโดยไม่ต้องมีบริบทมาก่อนเลย ครอบคลุมภูมิหลัง สถานะปัจจุบัน ผู้รับงานที่แนะนำ และรายละเอียดแต่ละงาน ทั้ง input, output, เช็กลิสต์, ขอบเขต และจุดที่พลาดง่าย

ผลลัพธ์ → เอกสารส่งต่องาน
calm-down triage

ทำให้ตัวเองใจเย็นลง

การซักแบบช่วยให้ใจเย็น สำหรับงานเร่งด่วนที่คุณกำลังจะลงมือทำเอง มันแตกความตื่นตระหนกออกเป็นส่วน ๆ ตัดสินใจเรื่องลำดับความสำคัญที่ยากที่สุด แล้วยื่นแผนรบให้คุณ พร้อมเวลาประเมินและแนวทางที่ฟันธงต่อแต่ละงาน

ผลลัพธ์ → แผนรบ (Battle plan)

มันทำงานอย่างไร

ทั้งสองโหมดใช้ลูปสี่จังหวะเดียวกัน มันไม่เคยให้คุณเขียนรายการงานเองตั้งแต่ศูนย์ — มันเสนอรายการมาให้แล้วให้คุณตอบรับ

  1. เสนอการแตกงาน อ่านบรีฟของคุณ เดารายการงาน แล้วขอยืนยันก่อนไปต่อ
  2. ซักทีละคำถาม แต่ละคำถามมาพร้อมคำตอบที่แนะนำ คำตอบที่กำกวมจะถูกท้วง และจะหยุดทันทีที่เอกสารสมบูรณ์พอจะอยู่ได้ด้วยตัวเอง
  3. เลือกรูปแบบ Markdown หรือ HTML (ธีมกระดาษแบบนี้)
  4. สร้างทันที ไม่มีขั้นตอนพรีวิว — เขียนและบันทึกเอกสารเลย แล้วบอกพาธที่แน่นอนให้คุณ

การตัดสินใจแบบ Triage

โหมด triage หยิบยืมวินัยทางวิศวกรรมเรื่อง triage มาใช้ — คือการตัดสินใจว่าอะไรต้องจัดการเดี๋ยวนี้ อะไรรอได้ และอะไรที่เราจะเดินจากไป ทุกงานต้องลงในกล่องใดกล่องหนึ่งเท่านั้น

P0

ต้องส่งให้ได้ ถ้าอันนี้พลาด ทั้งหมดล้มเหลว พวกนี้มาก่อน

P1

ควรส่งให้ได้ มีคุณค่าจริง แต่ตัดออกได้ถ้าเวลาหมด — โดยไม่ถือว่าล้มเหลว

CUT

ไม่ทำรอบนี้ ระบุชื่อให้ชัดแล้ววางมันลง

ทำไมการตัดทิ้งถึงช่วยให้ใจเย็น

ความตื่นตระหนกส่วนใหญ่ก็แค่ขอบเขตงานที่ยังไม่ถูกจัดเรียง การระบุชื่อสิ่งที่คุณ จะไม่ ทำ คือจังหวะที่ทำให้ทุกอย่างสงบลง — มันให้อนุญาตคุณหยุดแบกทุกอย่างไว้พร้อมกัน ถ้าทุกอย่างยังเป็น P0 อยู่ แปลว่าการ triage ยังไม่เกิดขึ้นจริง

สิ่งที่คุณจะได้

เอกสารที่ถูกบันทึกไว้ใต้ docs/ ในรูปแบบ Markdown หรือธีม HTML แบบกระดาษเงียบ ๆ แบบนี้ — โครงสร้างถูกขับด้วยเส้นขอบบาง ๆ และสีน้ำเงินเน้นเพียงสีเดียว ไม่ใช่การตกแต่ง ภาพรวมตั้งแต่ต้นจนจบ:

บรีฟ  →  เสนองาน  →  ซักถาม (ถาม-ตอบ)  →  [triage: P0 / P1 / cut]  →  สร้าง  →  docs/yyyy-mm-dd-topic.{md,html}
