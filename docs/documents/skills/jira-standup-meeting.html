jira-standup-meeting

Open your day with one command. The skill reads your Jira tasks, groups them by status, and tells you what to do first.

skills/work/jira-standup-meeting name: jira-daily-standup-meeting needs: Atlassian Rovo MCP

What it does

The skill gives you a morning summary of your Jira issues in the Tech Team project. It reads two lists: your issues in the open sprint, and your issues that changed in the last 7 days.

  • Task summary. Your issues, grouped as In Progress, Ready to Review, To Do, Done and Recently Updated.
  • Recommendations. Sprint health, carry-overs, stalled items and a numbered focus list for today. You do not have to ask for them.

It only reads. It does not change an issue or write a file unless you ask.

Prerequisites

  • The Atlassian Rovo MCP Server (https://mcp.atlassian.com/v1/mcp) is configured in your client.
  • You authenticated it with OAuth 2.1.
  • Your issues are in the Jira project Tech Team. The queries use this project name.
No MCP, no summary

If the Rovo MCP tools are not available, the skill tells you and stops. It does not guess your tasks.

How it works

  1. Ask. The skill asks for your Jira username or email address. It waits for your answer.
  2. Look up. It calls lookupJiraAccountId and uses the accountId, not your display name, in every query.
  3. Query. It runs two JQL queries at the same time with searchJiraIssuesUsingJql: open-sprint issues, and issues updated in the last 7 days.
  4. Merge. It merges the two lists by issue key. Sprint issues win, so the Recently Updated section shows only issues outside the sprint.
  5. Compute signals. It reads the raw data for the facts that drive the recommendations (see below).
  6. Summarise. It writes the task summary in Markdown. It leaves out empty sections.
  7. Recommend and offer. It adds the recommendations, then asks if you want more detail or a status update.

The queries

-- Active sprint issues
assignee = "{accountId}" AND project = "Tech Team" AND sprint in openSprints() ORDER BY status ASC

-- Recently updated (last 7 days)
assignee = "{accountId}" AND project = "Tech Team" AND updated >= -7d ORDER BY updated DESC

Each issue comes back with summary, status, priority, description, updated, customfield_10020, customfield_10014 and parent. customfield_10020 is the sprint array. The epic comes from customfield_10014 (classic projects) or parent (next-gen projects), and the summary shows it as the project name.

The signals

SignalHow the skill finds it
Sprint end dateThe sprint in customfield_10020 with state = "active" gives the endDate. The skill counts the days from today.
Review bottleneckThe number of issues in Ready to Review.
Carry-over itemAn issue that was in 3 or more sprints.
Stalled In ProgressAn In Progress issue with no update for more than 3 days.
Blocker signalThe summary or description contains “blocked” or “block”.

The focus order

The suggested focus list follows fixed rules, in this order:

  1. 3 or more issues in Ready to Review, and the sprint ends in 5 days or fewer: chase the reviews first.
  2. Any In Progress issue: wrap it up and move it to Ready to Review.
  3. A carry-over To Do with no description: add a description or defer it.
  4. A carry-over To Do with a description: start it now.
  5. Other To Do issues: in order of urgency from their summaries.

Nothing goes to disk. The skill writes a file only when you ask it to.

Common questions

Why does it ask for my username every time?
It needs your account ID for the queries. It asks first and looks up the ID, so the filter matches you and nobody with a similar name.
Can it read a project other than Tech Team?
Not as written. Both JQL queries use project = "Tech Team". To use another project, change the queries in the SKILL.md.
Why is an issue missing from Recently Updated?
It is probably in the sprint list already. The skill removes duplicates, and the sprint list wins.
What makes an issue a carry-over?
It was in 3 or more sprints. The skill counts the entries in the sprint field customfield_10020.
Will it change my Jira issues?
No. It only reads. At the end it offers to update a status, and it does that only if you say yes.

It’s working if

  • Every issue key in the summary links to its Jira page.
  • No issue shows in both a sprint section and Recently Updated.
  • The Recommendations section comes right after the summary, without a request.
  • The first focus item is an action you can start now, with an issue key.
  • No file appears in your repo after the run.

Where it fits

This skill opens the day. It tells you what to work on. Other skills in the work group help you during and after the work.

morning   → jira-standup-meeting → focus list → you work the issues
work done → progress-summary → Jira / Discord update
too much  → calm-down triage → battle plan

To post what you finished, use progress-summary. If the focus list feels too big, use calm-down in triage mode.
