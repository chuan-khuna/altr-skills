progress-summary

Tell it what you did, in any form. It gives you an update your team can read in ten seconds.

skills/work/progress-summary channels: JIRA · Discord

What it does

progress-summary takes raw notes, a git log, pasted text or the current conversation. It writes a clear, factual summary of the work you did, shaped for one channel: a JIRA comment or a Discord post.

The audience is your teammates. They know the project, so the skill keeps names they share and strips internal detail. It only prints the draft. You copy it and post it yourself.

When to use it

SituationUse
You finished some work and want to update the JIRA card.progress-summary (JIRA)
You want to tell your team channel what you shipped.progress-summary (Discord)
You want a start-of-day list of your own JIRA tasks, with recommendations.jira-standup-meeting
You hand work to someone else and they need full context.calm-down assign

Short version: progress-summary reports what you did. It does not plan what comes next for someone else.

Prerequisites

None for notes, git logs or conversation context. To start from a JIRA key such as PROJ-123, the skill uses the Atlassian MCP if it is available.

How it works

  1. Check the channel. If you did not say JIRA or Discord, the skill asks one short question and stops.
  2. Read the source. It uses pasted notes directly. From a git log, it drops noise commits such as merges, version bumps and fixups. From a JIRA key, it looks at recent activity and current state. If the source is unclear, it asks one question and stops.
  3. Filter. It keeps shared names, strips internal detail, and translates mechanics into plain cause and effect.
  4. Shape. It formats the text for the channel.
  5. Print. It gives you one block, formatted as the channel shows it.

Keep, strip, translate

ActionApplies to
KeepTask names, feature names, PR numbers, JIRA keys, component, service and tool names.
StripFunction names, file paths, variable names, internal config detail, commit SHAs.
TranslateImplementation mechanics into one plain sentence about the impact.

For example, not “fixed the null dereference in auth/session.ts:142” but “fixed a crash in the session handler that was dropping users on login.” Technical words like race condition or regression stay; your team knows them.

Print only

The skill never posts to JIRA or Discord. It prints the draft, and you paste it where it belongs.

Common questions

Can I just give it my git log?
Yes. It keeps the meaningful changes and drops merges, version bumps and fixups.
Why did it remove my file paths?
File paths and function names do not tell teammates the state of the work. The skill keeps the impact and drops the address.
What happens if my notes are vague?
It writes only what it knows and marks gaps, for example “details TBC”. It does not invent facts or owners.
Can it post the comment for me?
No. The output is print-only. You copy it and post it.
Why does it stop and ask “JIRA or Discord?”
The two channels need different shapes. One short question is faster than a draft in the wrong shape.

It’s working if

  • Every JIRA key, PR number and feature name from the source is still in the update.
  • The update has no file paths, function names or commit SHAs.
  • A Discord post is under 60 words and starts with a one-sentence TL;DR.
  • Nothing in the update is a fact that the source did not give.
  • You can paste the draft with no edits.

Where it fits

progress-summary closes the loop at the end of a piece of work. Use it after you finish or pause a task, when the team needs to know.

morning  → jira-standup-meeting → plan your day
work     → notes / git log / chat
done     → progress-summary → JIRA comment or Discord post

For a start-of-day view of your tasks, use jira-standup-meeting. To hand the work to someone else, use calm-down assign.
