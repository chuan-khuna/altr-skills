calm-down

Stop, think, then act. The skill turns a rough brief into a document that someone can start from with no other context.

skills/work/calm-down modes: assign · triage

What it does

calm-down has two modes. Both modes start from a short brief and end with one file on disk.

  • calm-down assign writes a handoff document. A teammate or an AI agent can read it and start work without asking you anything.
  • calm-down triage is for urgent work that you must do yourself. It sorts the scope into P0, P1 and a cut list, and gives you a battle plan.

Each mode asks you questions, one at a time. Each question comes with a recommended answer, so you can usually accept it with one word. The skill stops when the document is complete, not when it reaches a question count.

When to use it

SituationUse
You give work to another person or an agent, and you will not be there to answer questions.calm-down assign
You have a deadline in hours, too many tasks, and you feel panic.calm-down triage
You want to test a plan or design, with no deadline pressure.grill-me or grilling
You want a spec or tickets for a feature.to-spec, then to-tickets

Short version: assign is for someone else, triage is for you, now.

How it works

The two modes use the same loop. Only the questions and the output template change.

  1. Propose. The skill reads the brief and proposes a task breakdown at once. You confirm or correct it.
  2. Grill. The skill asks one question at a time, with a recommended answer. If an answer is vague, it asks again.
  3. Choose a format. You pick Markdown or HTML.
  4. Write. The skill writes the file immediately, with no preview, and tells you the path.

Assign mode

Assign mode asks about three areas, in this order:

  1. Context: what started the work, what is already done, and any hard constraint or deadline.
  2. Each task: the concrete input, the expected output, how to verify that it is done, and what can go wrong.
  3. Scope: what each task must not touch.

Expect 6 to 12 questions.

Triage mode

Triage mode follows Stop → Think → Act. It is shorter: 6 questions or fewer.

  • Stop. The skill names the task and the time that remains. It tells you that five minutes of thinking now saves time later.
  • Think. It asks what exists, what is missing, who must approve, and which constraints apply. Then it makes the triage call: every task goes into P0, P1 or the cut list.
  • Act. It gives one recommended approach for each P0 and P1 task, then writes the plan.
Why the cut list matters

Most panic comes from scope that nobody has sorted. When you name what you will not do, you can stop thinking about it. If you mark every task as P0, the skill pushes back: “If you only had half the time, which one would you keep?”

What it writes

ModeFileMain sections
assigndocs/yyyy-mm-dd-{topic}.{md,html}Background, Current State, Suggested Assignee, Tasks
triagedocs/yyyy-mm-dd-{topic}-triage.{md,html}Situation, What We Have, What’s Still Missing, The Triage Call, Tasks

Each task in an assign document has an input, an output, a checklist, an out-of-scope line and at least one gotcha. Each task in a triage plan also has a priority, a time estimate and one recommended approach.

A short assign task looks like this:

### Task 1: Rotate the staging API key

**Input:** Admin access to the vault; current key at `staging/api-key`
**Output:** New key in the vault; old key revoked

**Checklist:**
- [ ] `curl -H "Authorization: Bearer $KEY" $STAGING/health` returns 200
- [ ] Old key returns 401

**Out of scope:** Production keys

**Gotchas:**
- The worker caches the key for 10 minutes. Restart it after the change.

For HTML output, the skill copies references/html_boilerplate.html and fills it in. The boilerplate holds the full design system from references/DESIGN.md, so the skill does not write new CSS.

Common questions

Why does it propose a breakdown before it asks anything?
A wrong task list makes every later question wrong. When you confirm the list first, the rest of the session stays on the correct work.
Why is there no preview before it writes the file?
The grill already confirmed every part of the content. A preview adds one more step and does not add information. Edit the file after it is written if you want to change it.
Can I skip questions?
Yes. If the brief already answers a question, the skill skips it. You can also accept the recommended answer with one word.
Why must every task have a gotcha and an out-of-scope line?
The reader cannot ask you questions. The gotcha tells them what is likely to fail. The out-of-scope line stops them from doing extra work on wrong assumptions.
Does triage work for non-code work?
Yes. The triage call works for any urgent scope: a report, a demo, a release, or a move.

It’s working if

  • A fresh agent can start an assigned task with no follow-up question.
  • Every checklist item is a thing you can run or observe, not “make sure it works”.
  • The triage plan has at least one item in the cut list.
  • The session takes minutes, not most of the time that remains.
  • You feel calmer at the end than at the start.

Where it fits

calm-down sits between a vague request and real work. Use it after you know what to do, and before someone starts to do it.

rough brief → calm-down assign → handoff doc → teammate / agent works it
deadline    → calm-down triage → battle plan → you work P0, then P1

For deeper design questions, use grill-me first. To track the tasks as issues, run to-tickets on the handoff document.
