evergreen-note-writer

Give it your reading material. It gives back small notes, one idea each, with titles that say something on their own.

skills/productivity/evergreen-note-writer output: note files

What it does

evergreen-note-writer reads your sources and turns them into evergreen notes. An evergreen note holds one idea: a concept, a claim, a definition or an insight. You can refine it over time and link it to other notes.

Each note has four properties:

  • Atomic. One idea per note, not a summary of a whole source.
  • Concept-first title. An assertion (“X causes Y”), a question (“What is X?”) or a scoped definition.
  • Interlinked. It links to related ideas.
  • Standalone. You can read it without the source.

The skill never writes a file on its own. You review the content first, then you tell it where to save each note.

When to use it

SituationUse
You read an article, a paper or a set of files, and you want to keep the ideas as linked notes.evergreen-note-writer
You pasted some text and want a few atomic notes from it.evergreen-note-writer
You want one longer document from a conversation or a codebase feature.write-doc
You already have a note and only want to fix its English.quill-edit

Short version: use it when you want many small ideas, not one big summary.

How it works

The skill works in six steps. You approve the content and the save path before any file exists.

  1. Read. The skill reads every source you give: files, pasted text, web pages, MCP data or references. If there are many sources, it first summarises what it found across all of them.
  2. Ask about granularity. It asks how many notes you want, and at what level. The default is one note per distinct claim or insight.
  3. Propose. For each note, it writes a title, a short body in plain words, links to related concepts, and frontmatter if it fits your project.
  4. Review. You change titles or scope, merge or split notes, and add or remove links.
  5. Ask where to save. For each approved note, it asks for the path and filename.
  6. Create. It writes each file only after you confirm the path. It never overwrites a file without your permission.
No fixed schema

The skill does not assume a frontmatter schema, a folder structure or a link format. It asks you, or it follows what your project already uses, for example [[wikilinks]] in an Obsidian vault.

Common questions

Why does it ask about granularity before it writes anything?
The same source can give three notes or fifteen. When you choose the level first, the proposals match what you want.
Can I give it more than one source?
Yes. It reads all of them and summarises across them before it proposes notes. It does not handle each source in isolation.
Will it save files in a default folder?
No. It asks you for the path and filename of each note. It uses only what you tell it.
What if a file already exists at that path?
The skill does not overwrite it unless you give explicit permission.
What if one note covers two ideas?
The skill splits it into two notes. You can also ask it to merge or split notes during review.

It’s working if

  • Every title makes a claim, asks a question or defines a term.
  • Each note body covers exactly one idea.
  • You can read a note and understand it without the source.
  • No file appears before you approve its content and its path.
  • The body text is a rephrase, not a copy of the source.

Where it fits

evergreen-note-writer sits between reading and your note system. Use it after you collect material and before you link it into your vault.

sources → evergreen-note-writer → reviewed notes → files in your vault
note text → quill-edit → corrected British English

For one long document instead of many notes, use write-doc. To polish the wording of a note, use quill-edit.
